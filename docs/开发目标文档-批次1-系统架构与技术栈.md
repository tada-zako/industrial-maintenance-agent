# 开发目标文档（批次一）：系统架构与技术栈

## 1. 本批次结论

本项目定位为生产实习期间使用的简单演示 Demo，目标是展示“基于 Hermes Agent 的工业运维多工具调用流程”，而不是开发一个可长期维护、面向大量用户或直接用于真实工厂生产环境的软件系统。

项目重点是：

1. 能够运行 Hermes Agent；
2. 能够通过 MCP 工具查询设备、故障和维修知识；
3. 能够生成维修方案草案；
4. 能够通过 Vue 前端看板展示设备状态、问题、维修草案和 Agent 工作流；
5. 能够完成一次完整、可演示、可复现的故障处理流程。

在此范围内，系统不追求高并发、复杂权限、长期扩展、微服务治理、实时工业控制或真实设备写入。

## 2. 项目应用场景

项目采用“工业空压机运维”作为默认演示场景。

选择该场景的原因：

- 设备结构相对容易理解，适合在实习项目周期内完成；
- 可以自然设置压力、温度、振动、油位、运行状态等设备数据；
- 常见故障比较明确，例如排气压力异常、温度过高、振动异常、润滑不足；
- 设备、部件、故障现象、故障原因、维修措施和 SOP 之间容易建立知识图谱关系；
- 既能展示设备状态，又能展示 Agent 的故障查询和维修方案生成能力。

项目中的设备数据、故障记录、维修案例和运行状态以模拟或整理后的公开资料为主，不连接真实工厂设备，也不执行真实维修操作。

## 3. 总体技术栈

### 3.1 技术栈清单

| 层次         | 技术选择                        | 主要职责                                           |
| ------------ | ------------------------------- | -------------------------------------------------- |
| Agent 运行时 | Hermes Agent                    | 接收用户问题、规划任务、调用 MCP 工具、生成回答    |
| 工具协议     | MCP                             | 规定 Hermes 与业务工具之间的调用方式               |
| MCP 服务     | FastMCP                         | 实现设备查询、故障检索、知识查询和维修草案生成工具 |
| 后端查询接口 | FastAPI                         | 为前端提供设备、问题、草案和工作流的 HTTP 查询接口 |
| 业务数据库   | SQLite                         | 保存需要 CRUD 的设备、问题、草案和工作流数据     |
| 业务数据访问 | SQLAlchemy 2.x Async ORM       | 使用异步方式连接和访问 SQLite                   |
| 知识图谱数据库 | Neo4j                         | 保存设备、部件、故障、维修案例及知识图谱关系     |
| 前端框架     | Vue 3                           | 实现工业运维看板                                   |
| 前端语言     | TypeScript                      | 提供前端数据类型和接口类型约束                     |
| 前端构建工具 | Vite                            | 创建和运行 Vue 前端项目                            |
| 前端路由     | Vue Router                      | 管理总览、设备、问题、草案和工作流页面             |
| UI 组件库    | Element Plus                    | 提供表格、卡片、标签、表单、弹窗、时间线等基础组件 |
| 数据请求     | 原生 Fetch 封装                 | 完成必要的异步 HTTP 请求                           |
| 图表         | Apache ECharts                  | 展示设备状态和故障统计                             |
| 数据初始化   | JSON/CSV/Markdown + Python 脚本 | 提供演示数据和知识资料                             |
| 运行环境     | Docker Compose                  | 统一启动 Hermes、Neo4j 及项目自有服务              |

### 3.2 为什么选择 Element Plus

本项目是简单 Demo，主要开发工作由 Agent 完成，需要减少基础 UI 组件的重复开发。

Element Plus 具备较完整的 Vue 组件体系，能够直接满足本项目的表格、状态标签、卡片、抽屉、弹窗、分页和时间线需求，接入成本低于自行组合大量基础组件。

本项目暂不采用 shadcn-vue，原因是它更适合需要自行组织视觉系统和组件源码的项目，而当前 Demo 更关注业务流程和 Agent 能力验证。

## 4. 异步支持和依赖控制

### 4.1 必须支持的异步场景

系统只实现必要的异步能力：

- 前端请求 FastAPI 接口时显示加载状态；
- 前端请求失败时显示错误状态；
- Hermes 调用 MCP 工具时允许执行多个有依赖关系的查询；
- 后端访问 Neo4j 或读取数据文件时不阻塞必要的请求流程；
- 维修方案生成完成后，前端能够刷新并查看生成结果。

后端 SQLite 连接必须使用 SQLAlchemy 2.x 的异步 ORM，并使用 `aiosqlite` 作为 SQLite 异步驱动。FastAPI 请求处理、业务服务和数据库访问不得在异步请求路径中调用同步 SQLAlchemy Session。

推荐使用 `AsyncEngine`、`async_sessionmaker` 和 `AsyncSession` 管理数据库连接和会话。Neo4j 不属于 SQLAlchemy 的适用范围，访问 Neo4j 时使用其异步 Python Driver；MVP 不要求引入复杂的连接池和事务协调机制。

### 4.2 明确不实现的异步能力

本项目暂不实现：

- WebSocket 实时推送；
- SSE 流式工作流展示；
- 消息队列；
- 后台任务调度系统；
- Redis 缓存；
- 分布式任务执行；
- 高并发连接管理；
- 复杂的前端请求缓存和自动失效策略。


## 5. 前后端功能边界

### 5.1 Hermes Agent

Hermes 负责：

- 接收自然语言运维问题；
- 识别设备和故障现象；
- 决定需要调用哪些工具；
- 组织多个工具调用；
- 汇总工具结果和知识图谱证据；
- 生成维修方案草案；
- 向用户说明判断依据和安全注意事项。

Hermes 不负责：

- 直接访问浏览器页面；
- 直接操作 Neo4j 数据库；
- 直接执行真实设备控制；
- 替代 Vue 前端看板；
- 维护一个额外开发的聊天 UI。

### 5.2 FastMCP Server

FastMCP Server 负责提供 Hermes 可以调用的业务工具，包括：

- 设备信息查询；
- 设备运行状态查询；
- 历史故障查询；
- 故障原因和维修案例检索；
- 知识图谱查询；
- SOP 查询；
- 维修方案草案生成；
- 维修方案基本校验；
- 工作流记录保存。

MCP 工具默认采用查询和生成草案模式，不执行真实设备写入和真实维修操作。

### 5.3 FastAPI

FastAPI 只负责向 Vue 看板提供只读 HTTP 接口，例如设备列表、设备详情、问题列表、维修草案和工作流详情。

FastAPI 不负责：

- 运行 Agent 主循环；
- 替代 Hermes 进行自然语言推理；
- 直接向浏览器暴露 Neo4j；
- 实现 MCP 协议本身。

FastMCP 和 FastAPI 可以共用同一套业务服务和数据访问代码，避免重复编写设备查询和知识查询逻辑。

### 5.4 Vue 前端

Vue 前端负责：

- 展示设备运行状态；
- 展示待处理故障和注意事项；
- 展示历史维修方案草案；
- 展示知识证据；
- 展示 Agent 多工具调用流程；
- 提供进入 Hermes 对话 UI 的入口。

Vue 前端不负责：

- 实现新的 Agent 对话系统；
- 直接调用 MCP；
- 直接访问 Neo4j；
- 执行设备控制指令；
- 实现复杂的用户权限体系。

## 6. 代码实现范围

### 6.1 需要自主实现的代码

项目需要实现：

- FastMCP Server 入口；
- MCP 工具函数；
- Neo4j 数据访问和查询函数；
- 基于 SQLAlchemy Async ORM 的 SQLite 模型、Session 和仓储函数；
- 设备、故障、维修案例和知识图谱初始化脚本；
- FastAPI 只读查询接口；
- 前后端共用的数据结构或响应模型；
- Vue 页面、路由和基础布局；
- Element Plus 页面组件组合；
- 设备状态和故障统计图表；
- Agent 工作流时间线；
- Hermes Web UI 跳转入口；
- 必要的单元测试和接口测试；
- Docker Compose 服务配置。

### 6.2 不需要实现的代码

项目不需要：

- 修改 Hermes 源码；
- 从零实现 Agent 框架；
- 从零实现 MCP 协议；
- 从零开发聊天页面；
- 开发真实工业协议接入；
- 接入 PLC、SCADA 或真实传感器；
- 实现生产级用户认证和权限系统；
- 实现高并发优化和分布式部署；
- 实现真实维修工单闭环。

## 7. 服务结构

最终开发结构暂定为：

```text
Hermes Agent
    │ MCP Tool Calling
    ▼
FastMCP Server ───────┐
    │                 │
    └──── 共享业务服务 ──── Neo4j
                          ▲
                          │
Vue Dashboard ── HTTP ── FastAPI
```

其中：

- Hermes 是 Agent 入口；
- FastMCP 是 Agent 工具入口；
- FastAPI 是前端数据入口；
- Vue 是展示入口；
- Neo4j 是主要业务数据和知识图谱存储；
- 共享业务服务负责减少 FastMCP 与 FastAPI 的重复逻辑。

6. 确认系统只实现必要异步能力；
7. 确认系统不追求高并发和长期生产化；
